Los proyectos MCP también consumen componentes de negocio y de datos. PsycoApp.Entities contiene los modelos compartidos, y PsycoApp.utilities reúne utilidades comunes.
2. Proyectos de la solución
Proyecto	Responsabilidad principal
PsycoApp.site	Sitio web para usuarios. Contiene controladores, modelos de vista, vistas Razor y recursos web (CSS, JavaScript, imágenes y plugins). La estructura observada es MVC con vistas Razor, no una organización típica de Razor Pages.
PsycoApp.api	API HTTP que expone operaciones de la aplicación mediante controladores. Configura autenticación JWT, autorización, CORS y sesión de errores.
PsycoApp.BL	Capa de negocio. Incluye clases para citas, caja, pacientes, psicólogos, usuarios, reportes, productos y otros dominios.
PsycoApp.DA	Acceso a datos. Contiene clases *DA, conexión SQL y scripts de base de datos y procedimientos almacenados.
PsycoApp.Entities	Entidades y DTO usados entre las capas, por ejemplo Cita, Paciente, Usuario, Caja, Pago, Empresa y Sede.
PsycoApp.utilities	Funciones compartidas, como llamadas a API, helpers, logging y utilidades.
PsycoApp.mcp	Proyecto MCP con herramientas y servicios relacionados con citas; incluye modelos de solicitud y respuesta.
PsycoMCPServer	Segundo host MCP, con herramientas y servicios propios, entre ellos herramientas para citas y servicios de planes.

3. Tecnologías y configuración
Los proyectos de aplicación y bibliotecas principales apuntan a .NET 10. La excepción detectada es PsycoApp.utilities, que apunta a .NET Core 3.1. Esa diferencia merece revisión de compatibilidad y de soporte.
API
En PsycoApp.api/Startup.cs se observó:
•	Autorización global para los controladores.
•	Autenticación Bearer mediante JWT, con validación de emisor, audiencia, firma y expiración.
•	Parámetros de JWT configurados mediante claves como Jwt:Key, Jwt:Issuer y Jwt:Audience.
•	Middleware de routing, CORS, autenticación y autorización.
•	Controladores para citas, pacientes, caja, usuarios, psicólogos, reportes, configuración, encuestas, sedes, entre otros.
Sitio web
En PsycoApp.site/Startup.cs se observó:
•	MVC con vistas y compilación Razor en ejecución.
•	Sesión con una duración configurada de dos horas.
•	Antiforgery con la cabecera RequestVerificationToken.
•	Integración de PWA.
•	Un middleware que recupera el JWT de la sesión y lo pasa a ApiCaller, lo que apunta a que el sitio actúa como cliente de la API.
•	La ruta raíz lleva a la página pública de SaaS; la ruta convencional por defecto apunta a Login.
MCP
Hay dos proyectos MCP en la solución. PsycoApp.mcp incluye un paquete ModelContextProtocol en versión preliminar; ambos proyectos contienen modelos y herramientas para citas. La revisión de sus dependencias y de sus operaciones no fue exhaustiva.

5. Esquema de base de datos observado
El archivo principal es PSYCO_APP/SQL/SchemaSQL.sql. En el fragmento revisado aparece la base PsycoApp, con tablas, funciones y procedimientos almacenados.
Empresas y sedes
•	tbl_empresa: empresa, nombre y estado.
•	tbl_sede: sede, nombre, estado, centro e identificador de empresa.
•	Relación declarada: tbl_sede.Id_empresa → tbl_empresa.Id.
Esto proporciona una base para separar datos por empresa y sede.
Usuarios y permisos
•	tbl_usuario: datos de usuario, tipo, documento, correo, login, sede y contraseña.
•	tbl_tipousuario: tipos de usuario.

•	Relación declarada: token.user_id → tbl_usuario.id_usuario.
En el fragmento aparecen funciones de cifrado y descifrado de contraseña basadas en DecryptByPassPhrase.
Psicólogos

6. Observaciones importantes
1.	Frameworks mezclados: PsycoApp.utilities sigue apuntando a .NET Core 3.1, mientras los demás proyectos principales usan .NET 10. Conviene verificar si existe una actualización pendiente o una razón deliberada para mantenerlo así.
2.	Dos hosts MCP: la solución contiene tanto PsycoApp.mcp como PsycoMCPServer. No está determinado si ambos cumplen funciones distintas, si uno es legado o cómo se despliegan.
3.	Esquema distribuido: además de SchemaSQL.sql, hay numerosos scripts históricos y parches en PsycoApp.DA/SQLScripts y en la API. Para saber cuál es el esquema vigente, habría que contrastar esos scripts con la base de datos real.
4.	Relaciones que requieren confirmación: algunas columnas parecen identificadores relacionados con otras tablas, pero no se verificaron todas las restricciones FK en el tramo leído.
5.	Seguridad: el proyecto configura JWT y utiliza funciones SQL de contraseñas. Para evaluar si el almacenamiento de credenciales y la configuración de secretos son adecuados, habría que revisar la implementación y la configuración desplegada, sin exponer valores sensibles.
6.	Pruebas y estado funcional: esta revisión describe la estructura; no ejecuté compilaciones ni pruebas, y no confirma que cada módulo funcione actualmente.
